# Taste — Command Code user preferences
- Wants documents/PDFs to be scannable rather than dense: the opening page should read as a bulleted fact sheet, and later pages should carry charts, graphs, and visuals instead of long prose. Explicitly objects to pages that feel "cramped and wordy." Confidence: 0.65
- Readily accepts readability/polish suggestions on collateral (larger detail type, no dead space in cards, clickable links, proper PDF metadata) — a terse "regenerate with your changes" is approval to apply them all without further discussion. Confidence: 0.55
- Treats the live site's own copy as the source of truth for product facts and terminology when producing collateral ("from the site's own copy"). Confidence: 0.5
- Expects outdated vendor/product naming to be replaced everywhere so it matches the current official wording (e.g. Vertex AI → Gemini Enterprise Agent Platform) — not just in the deliverable, but across site source, README, and agent-skill/well-known docs. Confidence: 0.7
- When the assistant flags a discrepancy such as "this repo's source still says X, don't deploy from this branch," prefers that the assistant just fix the source ("update that one") rather than leaving the caveat for later. Confidence: 0.6
- Wants diffs kept surgical: only the intended edits, no whole-file reformatting or unrelated churn from running a formatter across touched files. Confidence: 0.5
- Distinguishes product naming from literal interface strings — command-line flags such as `--format vertex` shouldn't be renamed as part of a copy/terminology sweep. Confidence: 0.5
- Does not want business registration/tax identifiers (WA UBI, EIN) published on public surfaces — company page, marketing PDFs, agent-skill/well-known docs — and expects only the jurisdiction ("Washington, United States") to remain; wants every public occurrence found and stripped, not just the one they noticed. Confidence: 0.8
- Extends that caution to infrastructure identifiers such as the Google Cloud project ID: scrub them from public site copy and agent-facing docs, but allow them to stay in a partner/verification PDF when an outside reviewer (e.g. Google for Startups) needs to confirm the workload. Confidence: 0.7
- For privacy/removal changes, expects confirmation that the identifier is gone from regenerated artifacts (rebuilt PDFs), the preview deploy, and the live domain — plus a heads-up when the old values remain in git history or cached copies. Confidence: 0.6
- Gives operational instructions as one-word or one-line commands (e.g. "deploy", "can you regenerate with your changes") and expects the agent to work out the mechanism itself — inspect the repo, install/build, deploy, regenerate the artifact, then verify the result — rather than being told each step. Confidence: 0.55
